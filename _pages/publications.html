Research

How do language models get better, and what stops them?

A language model system improves through three levers: the harness it runs in, the compute it spends at test time, and the weights it learns in training. Each project below starts with a measurement that exposes what limits one lever, then builds a method aimed at that mechanism.

01 · Harness · MILO

When harness search stalls, let the search rewrite itself

An agent is a model plus a harness: the prompts, tools, memory and control flow around it. Automated harness search usually fixes its strategy in advance, so it plateaus. MILO co-evolves the harness and its own search. Islands of harnesses evolve in parallel, and an orchestrator diagnoses stalls and intervenes by grafting lineages and reassigning mutators.

It sets state-of-the-art results on Terminal-Bench 2.1, PaperBench and DeepSWE. Drag through the 28 rounds of one search run below.

02 · Test-time compute · Hermes

Extra context is a liability until the model learns to use it

Spreading test-time compute over many context windows means deciding what each fresh context should do and what it hands back. Hermes leaves those decisions to the model. Out of the box, a 4B model gets worse with more contexts. After Hermes-Learn (SFT, then RL), it beats a single context with the same total token budget on all four math benchmarks.

03 · Training · SCOUT

On-policy for the student is off-policy for the teacher

In on-policy distillation the student writes the response and a stronger teacher scores every token of it. But the teacher was trained to continue its own reasoning. The deeper into a student's response, the further the text drifts from anything the teacher would write.

You can measure this directly: cut a student response partway and ask the teacher to finish it. SCOUT then trains the teacher with RL to continue student-written prefixes.
